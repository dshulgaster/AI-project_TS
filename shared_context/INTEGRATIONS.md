# 🔗 Архитектура и Спецификация Интеграций (INTEGRATIONS.md)

В данном документе описаны существующие и проектируемые способы интеграции между **TrackStudio (TS)**, **MS Project Server (MSP)** и созданными продуктами.

---

## 1. Схема Интеграционных Потоков

```
 ┌──────────────────────┐               ┌────────────────────────┐
 │  MS Project Server   │               │   TrackStudio (TS)     │

            │                                       │

            │                                       │

                ┌────────────────────────┐

                │ (PlanFact_Dashboard)   │
                └────────────────────────┘
```

## 2. Детализация Интеграций

### 2.1 TrackStudio (TS) -> Chrome Extension
- **Метод**: Парсинг DOM дерева браузера на лету (Content Script `content.js`).
- **Формат данных**: HTML таблицы подзадач (`tr`, `div.treeTable-row`), текста комментариев и шапки запроса.
- **Особенности**: Выполняется на стороне клиента в Chrome, не требует отдельной авторизации в API TS (использует сессию текущего пользователя).

### 2.2 TrackStudio (TS) -> PlanFact Dashboard
- **Метод**: Периодический экспорт дампа данных (`ts_export.json` / standalone PowerShell/Python экспортер).
- **Формат данных**: JSON структуры запросов, истории переходов статусов и списаний.
- **Особенности**: Python-скрипт обрабатывает JSON и собирает статический `PlanFact_Dashboard.html`.

### 2.3 MS Project Server <-> TrackStudio / MSP Dashboard
- **Чтение из MSP**: OData API / SQL Views MS Project Server или загрузка экспортированных файлов WBS (XML / Excel).
- **Синхронизация с TS**:
  - Скрипт (Python / Node.js) сопоставляет WBS задачи MSP с подзадачами TS по идентификатору запроса (`#XXXXXXX`).
  - **Публикация комментариев**: Автоматическое добавление сгенерированного планового комментария в TS через REST API TS / HTTP POST запросы с авторизационными куками.

---

## 3. Требования к Безопасности и Авторизации
- Все учетные данные (логины, пароли, API-токены) хранятся исключительно в файле `.env` (который занесен в `.gitignore`).
- Браузерное расширение использует существующие сессионные куки пользователя TrackStudio и не сохраняет пароли.
