# Дорожная карта Colvir projects

## 1. Цель проекта

Создать единую цепочку контроля трудозатрат вокруг TrackStudio и MS Project Server:

1. Быстро получать план-факт по отдельному запросу прямо в TrackStudio через Chrome Extension.
2. Сопоставлять календарный план MSP с задачами и вехами TrackStudio, формировать плановый комментарий и публиковать его в TS.
3. Регулярно собирать портфельный дамп TrackStudio и строить автономный аналитический дашборд для руководителей и менеджеров.

Общее правило для всех компонентов: фактические списания распределяются по пяти интервалам жизненного цикла запроса, а часы родительской категории не суммируются повторно, если доступны часы дочерних задач.

## 2. Целевая схема

```text
MS Project Server --(OData/XML/Excel)--> MSP Integration
                                           | план, вехи, сверка
                                           v
TrackStudio ------(DOM/API/экспорт)----> общий расчет Plan/Fact
      |                                    |                |
      +--> Chrome Extension                +--> PlanFact Dashboard
           (один запрос)                        (портфель)
```

## 3. Этапы реализации

### Этап 0. Уточнение контрактов и эталонных данных

**Результат:** зафиксированы форматы и правила, на которых смогут работать все три продукта.

- Описать схему `ts_export.json`: запрос, подзадачи, списания, историю переходов, плановые оценки, ответственного, банк и проект.
- Описать формат входных данных MSP: WBS, идентификатор запроса, роли, даты и трудозатраты.
- Определить единицы измерения и конвертацию `ч.` <-> `ч.д.`.
- Зафиксировать приоритет и допустимые варианты названий операций-вех.
- Подготовить небольшой обезличенный fixture: один запрос с раскрытыми задачами, свернутой категорией, пропущенной вехой и нарушением SLA.

**Критерий готовности:** один эталонный запрос дает заранее проверяемые суммы по всем пяти фазам.

### Этап 1. Общий расчетный слой

**Результат:** единый алгоритм, который можно использовать в расширении и Python-пайплайне.

- Реализовать поиск границ `T_po_boundary`, `T_dev_start`, `T_accept_start`, `T_release`.
- Реализовать полуинтервалы модели: ПО, ОА, Реализация, Приемка, Стабилизация.
- Добавить `defaultPhase` для случаев, когда дата отдельного списания недоступна.
- Реализовать защиту от двойного счета: при наличии дочерних списаний исключать агрегированную строку родителя.
- Считать план, факт, отклонение и SLA-флаг ПО (`> 5 дней`).
- Добавить обработку неполных и некорректных записей с диагностикой, не прерывая весь расчет.

**Критерий готовности:** unit-тесты покрывают границы дат, одинаковые даты, пропущенные вехи, fallback и родительские строки.

### Этап 2. Chrome Extension для одного запроса

**Результат:** рабочий on-demand виджет в TrackStudio.

- Создать Manifest V3, service worker `background.js` и `content.js`.
- По клику на иконку отправлять `toggleWidget`; не внедрять UI автоматически при загрузке страницы.
- Реализовать устойчивый DOM-парсер строк `tr` и `div.treeTable-row`.
- Отфильтровать комментарии, историю и служебные блоки.
- Распознавать дочерние задачи и свернутые категории `0/5`.
- Подключить общий расчет фаз, SLA и переключение `ч.д.` / `ч.`.
- Реализовать режимы `min`, `mid`, `max`, копирование Markdown для Notion и экспорт `.xls`.

**Критерий готовности:** на тестовой странице расширение показывает те же суммы, что эталонный расчет, и не считает родителя дважды.

### Этап 3. Пайплайн выгрузки TrackStudio

**Результат:** повторяемый источник данных для портфельного дашборда.

- Определить способ получения дампа: API или автономный экспортер.
- Реализовать загрузку запросов, истории, WBS/плана, подзадач и списаний.
- Добавить пагинацию, повтор сетевых запросов и журнал ошибок.
- Валидировать схему перед расчетом и сохранять версию формата.
- Исключить секреты из кода; использовать `.env` и `.gitignore`.

**Критерий готовности:** команда экспорта стабильно формирует валидный `ts_export.json` на тестовом и рабочем объеме данных.

### Этап 4. PlanFact Dashboard

**Результат:** автономный HTML-отчет по портфелю.

- Создать `generate_dashboard.py` на Python 3.10+ с `pandas`, `jinja2` и JSON.
- Агрегировать сотни тысяч списаний до компактной структуры для браузера.
- Встроить данные в HTML как JSON data island.
- Реализовать фильтры по банку, проекту, статусу S1-S6, менеджеру, SLA и номеру/названию запроса.
- Добавить графики Plan vs Fact по фазам, топ-10 перерасходов и SLA.
- Добавить сворачиваемую таблицу с отклонениями и детализацией по фазам.
- Сделать итоговый HTML полностью автономным: без сервера и внешнего интернета.

**Критерий готовности:** сгенерированный файл открывается локально, фильтруется на рабочем объеме и совпадает с агрегатами расчетного слоя.

### Этап 5. MSP Integration Dashboard

**Результат:** контролируемый обмен планом между MSP и TS.

- Реализовать импорт MSP через OData, XML и/или Excel с единым внутренним форматом.
- Сопоставлять WBS и запросы TS по идентификатору `#XXXXXXX`.
- Сверять даты вех, роли и плановые трудозатраты с данными TS.
- Показывать расхождения по срокам и структуре.
- Генерировать плановый комментарий и копировать его в буфер.
- Добавить экспорт `.xlsx` / `.xls`.
- Реализовать публикацию комментария в TS только после явного подтверждения пользователя; сетевые ошибки и частичные ответы должны быть видны в отчете.

**Критерий готовности:** для тестового запроса можно пройти путь импорт -> сопоставление -> просмотр расхождений -> генерация -> подтвержденная публикация.

### Этап 6. Сквозная проверка и эксплуатация

**Результат:** инструменты готовы к регулярному использованию.

- Сверить один и тот же запрос в расширении, портфельном дашборде и MSP-модуле.
- Провести нагрузочную проверку DOM и больших JSON-дампов.
- Проверить отсутствие секретов в репозитории и итоговом HTML.
- Добавить README с командами запуска, примерами входных файлов и схемой ошибок.
- Настроить регулярное обновление дампа и генерацию отчетов.
- Зафиксировать версию схемы данных и журнал изменений бизнес-правил.

## 4. Приоритет MVP

1. Контракт `ts_export.json` и fixture.
2. Эталонный расчет пяти фаз и тесты.
3. Chrome Extension: парсинг, расчет, виджет, копирование.
4. Python-генератор PlanFact Dashboard.
5. Экспорт TrackStudio и автоматическое обновление.
6. MSP-импорт и сверка.
7. Публикация комментариев в TS и расширенные интеграционные сценарии.

Такой порядок сначала дает полезный локальный результат и одновременно проверяет самую рискованную часть проекта — корректность учета факта.

## 5. Основные риски

- **Нестабильный DOM TrackStudio:** держать несколько селекторов, фильтры служебных блоков и fixture реальной страницы.
- **Разные названия операций:** использовать словарь синонимов и явно отображать пропущенную границу.
- **Двойной счет:** тестировать раскрытые и свернутые уровни отдельно и хранить происхождение каждой суммы.
- **Неполные даты:** применять `defaultPhase` только по формальному правилу, не скрывая fallback в UI.
- **Большие объемы:** агрегировать в Python, передавать в браузер компактные данные, измерять время фильтрации.
- **API и безопасность:** `.env`, таймауты, повторы, маскирование секретов в логах и ручное подтверждение публикации.
- **Расхождение компонентов:** общий контракт и набор golden-тестов для расширения и Python-генератора.
